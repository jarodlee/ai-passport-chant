# 佛音播放器第二版

绿色与暖金色的 240 × 320 专用界面替换硬件测试菜单。开机进入主页，同时以
80% 音量离线循环播放《心经长版》。内置五首录音：用户指定 YouTube 来源中的 8:30
大悲咒片段（510.000 秒）、观音菩萨圣号 37.329 秒、消灾吉祥神咒 76.643 秒、
《心经》305.850 秒，以及另一段 YouTube《心经》长版节选 290.000 秒。配合
扩大的应用分区，采用 11.025 kHz 单声道 IMA ADPCM 放下五首曲目；
原始 MP3 保留在本地。曲目、模式和佛音音量
重启复位；Cindy 回复音量单独保存，重启后保留。

## 页面与按键

- 主页：顶部第一行显示当前 Wi-Fi 名称，第二行显示本地日期时间（CST，未校时
  显示 `--`）；上下选择扫描 Wi-Fi、二维码、佛音曲库、安庆天气、连接 Wi-Fi、语音音量、Cindy 对话，
  选中项用大号标题字体并在两侧显示 ▶ ◀。
- 曲库：上下选择曲目或循环模式，确定播放或切换单曲／顺序循环。
- 播放：确定暂停或继续，上下以 5% 步长调节佛音音量，范围 0–90%。
- 任意页面长按确定或双击上键返回主页；从配网页返回同时关闭设备热点。
  独立电源键由硬件锁存控制，固件无法读取，不能改作返回键。
- 天气：确定请求刷新；安庆固定坐标北纬 30.54、东经 117.06，显示摄氏温度、
  WMO 天气状况、湿度、观测时间，以及“刚刚刷新 / X 分钟前刷新”；是否过期按
  观测时间的真实时钟判断，与开机时长无关。
- 网络：显示当前已连网络名和 IP，内容控制在七行内；菜单为手机配网、选择
  已存网络、扫描周边网络、忘记本应用保存的网络。配网中点确定关闭热点。选择
  已存网络进入列表，上下选择、确定连接，选中项保存为下次优先网络；列表最多
  六组并标出当前项。扫描页按信号强弱列出最多八个周边 AP，显示名称、dBm、
  信道，`*` 表示加密，确定可重扫。网络名按可打印 ASCII 显示，其它字节显示为
  `?`（界面字体为固定子集）。忘记网络需再次确定，移动选择则取消确认。
- Cindy：按住说话，语音播报回复。Mac 将每条回复渲染成 224×168 的 1 位位图，
  设备用 LVGL 索引画布显示，因此任意中文回复都不需要完整字库。文字只属于
  Cindy 页，离开时清除；播报中按上键会立即停止播报并回主页。录音、查找、上传、
  思考、播报各有固定状态提示。
- 语音音量：上下以 10% 步长调节回复音量，范围 20–100%，保存在 NVS
  `chant_cfg`；确定播放短提示音。佛音音量与回复音量相互独立，佛音音量仍
  在重启后复位。

电量始终在右上角，无法读取时显示 `--%`。60 秒无按键后降低背光，按键恢复；
不因自动休眠中断播放。原测试界面仅保留为参考与测试材料，不编入本应用。

## NFC 的硬件限制

主页提示“手机顶部靠近背部标签”。用户已确认 iPhone 能出现通知，目前标签
打开 `folotoy.cn`；希望改为 `https://www.lxj.ai`，尚未通过手机写入并复测。
本设备的 NTAG213 是供手机读取的**被动标签**，没有面向 MCU 的 BSP 接口。
固件不能扫描其它标签、检测手机是否扫描、改写标签，也不能报告识别成功。
本版不改动标签内容或 `cardid` 分区。

如标签允许写入，可用 iPhone 上的 NFC Tools：写入 → 添加记录 → URL / URI，
填写 `https://www.lxj.ai`，确认后点“写入”，将手机顶部靠近设备背部标签直到
完成。关闭应用后再次靠近，检查通知打开的目标。具体操作见
[NFC Tools 官方说明](https://www.wakdev.com/en/knowledge-base/how-to-guides/how-to-write-a-link-url-on-an-nfc-chip.html)。
若应用报告标签只读，应先核对锁定状态；USB 固件不能解除标签的永久只读锁定。

## 手机配网

进入“连接 Wi-Fi → 手机配网”，手机连接屏幕显示的 `Passport-XXXX` 热点，
无需密码直接连接，然后手动打开 `http://192.168.4.1`。
不提供强制门户或 DNS 拦截。填写 2.4 GHz 网络名（UTF-8 编码 1–32 字节），
开放网络密码留空，WPA2 密码为 8–63 位可打印英文字符。不支持仅 WPA3 网络，
当前可在 Wi-Fi 页按需扫描附近网络，但配网页本身不列出 SSID。

配网页只对热点客户端开放：接受 192.168.4.0/24 的客户端、套接字本地地址
为 192.168.4.1，或带 `Host: 192.168.4.1` 的请求（部分手机的门户浏览器读不到
套接字地址）。页面和错误页都声明 UTF-8，中文另外做了 HTML 实体编码（JS 用
`\u` 转义），即使门户浏览器忽略字符集也不会乱码。热点仅允许一部手机接入；新配网连接成功后
15 秒关闭，或十分钟后自动关闭，也可主动结束。只有匹配所提交网络名且取得 IP
后，才将凭据作为一个 NVS 数据项保存，错误密码不会保存。重启自动重连，连续
失败后改为每 30 秒重试。失败的重新配网不会覆盖上次成功保存的网络，重启仍
可恢复。保存失败会显示提示，不会擦除整个分区；忘记网络只清理 `chant_wifi`
中的网络记录并保留初始化标记，同时保留其它 NVS 与身份数据。扩大应用分区时已移除未使用的 storage 分区。

天气通过 HTTPS 获取，验证证书并等待 SNTP 校时，单次 I/O 超时 8 秒，响应上限
4 KB，检查观测数据时间。每次进入天气页都会立即刷新一次，成功后仍每十五分钟更新，失败一分钟后重试；
刷新过程显示“正在刷新”，超过三十分钟的数据明确标为过期，刷新失败保留上次
结果并提示。Wi-Fi 名称按可打印 ASCII 显示
（其它字节为 `?`），不显示任意下载文本。电脑请求 API 成功不代表设备联网已经验收。

## 实现与验证

不修改 BSP。唯一音频任务拥有编解码器、播放状态和硬件，每次解码 512 个采样；
按键回调只入队。界面持有 BSP 的 LVGL 锁，只更新变化的标签，读取音频与网络
快照。网络任务管理 Wi-Fi、设置与 HTTPS；HTTP 回调验证输入后入队。保存或忘记
网络前，音频任务短暂停用编解码器，写入完成后从原位置继续；恢复时先调用
`bsp_audio_wake()` 再设置格式，缺少唤醒会表现为切换已存网络后“音频不可用”。关闭蓝牙为 Wi-Fi
和 TLS 留出内部 RAM。

`./tools/validate.sh` 检查仓库、菜单导航、曲目循环、音量与错误恢复、配网输入
边界、天气值和过期逻辑、独立解码对照、五首录音完整性、中文覆盖，以及独立的
ESP-IDF 5.5.3 编译和合并镜像验证。字体生成还逐像素回读校验。交付记录保存
本次镜像身份与实际设备结果，编译成功不代表硬件通过。

待真机验证：所有页面排版、按键、11.025 kHz 音调和音质、完整曲目和列表循环、暂停、
背光、电量、手机配网、错误密码恢复、保存后重启与忘记网络、HTTPS/SNTP 天气、
联网同时播放的内存余量和供音间隔。语音对话按用户选择暂缓。

[素材来源与重新生成方式](../../assets/README.zh_CN.md)。录音公开可下载不等于获得
再分发许可，当前只用于用户自己的本地设备构建。

## 保持实测分区

| 分区 | 偏移 | 大小 |
| --- | --- | --- |
| nvs | 0x9000 | 0x6000 |
| phy_init | 0xF000 | 0x1000 |
| factory | 0x10000 | 0x7E0000 |
| cardid | 0x7F0000 | 0x4000 |

经用户同意后使用匹配归档中的引导器（`0x0`）、分区表（`0x8000`）和应用
（`0x10000`）分段刷写，不整片擦除。合并镜像用于明确的完整刷新，可能重置
NVS／PHY 数据；编译成功本身不授权刷机。

2026-10-18 的重分区保持 `nvs`、`phy_init` 偏移不变，将 `factory` 扩大到原
`storage` 区域，并把 `cardid` 移到 `0x7F0000`。刷写前已把 `nvs`、`cardid`、
`storage` 和旧分区表读回本地备份；`cardid` 按字节恢复到新位置并用哈希核对。
Wi-Fi 记录与语音音量保存在 `nvs` 中，升级后保留。

## 按住说话与 Cindy 桥接（第三版）

Cindy 位于主页最后一项。语音回复中按下确定即可打断播报并保留本次按键请求；等音频下载任务退出后立即转入录音，中间不重开佛音音频格式。HTTP 正文读取超时缩短为250毫秒，暂时性 EAGAIN 会重试。旧任务的网络清理推迟到下一次录音结束后，避免阻塞麦克风启动。若在真正开始播报前打断，路由发现、首次TLS连接仍可能耗时；短超时在收到响应头后生效。上键退出会取消当前对话和待启动录音。Cindy 页面已去掉同一网络的提示。按住确定直到出现录音提示，讲话最多八秒，松开发送；对话结束后上键返回。对话期间佛音暂停，结束后从原位置继续。过短录音拒绝发送。设备状态提示使用固定字库，回复同时以 Mac 渲染的 1 位位图显示在屏幕上，
位图由 `/v1/jobs/<id>/text` 提供。Mac 在发送前对 Tingting 的 PCM 做峰值归一化；
设备播放回复时应用已保存的语音音量。

本地配套 `ai-passport-bridge` 包使用随包 ARM64 whisper.cpp tiny 多语言模型（CPU/Accelerate）识别语音，通过 Cindy 正式的普通 Tasks 接口在独立、可见的对话任务中取得简短回答，再用 macOS Tingting 生成 16 kHz 语音。快速回答通道实测不可用后，用户明确选择使用现有 Cindy 任务通道。插件创建自己的可见任务，使用独立工作目录及默认 ask 权限，允许按用户要求只读搜索、查阅公开网页，查询实时信息时须核实并简述来源及日期，无法核实时如实说明；禁止本地文件、命令、发消息及访问其它任务。普通闲聊无需搜索。这是工作范围约束，不代表操作系统沙箱保证。插件包含常驻原生 Node 工作进程；status 工具可启动和停止 HTTP 18765、认证 UDP 发现 18766。临时录音文件权限受限，在150秒后或停止服务时删除。Mac 必须唤醒并运行 Cindy。局域网发现要求设备处于同一可信网络且路由器未启用设备隔离；可选 HTTPS 入口支持不同网络。识别和播报不需要云端密钥，回答文本按已配置的任务模型处理，可在 Cindy 任务列表查看对话记录。

每套本地构建生成随机配对密钥，分别放在被 Git 忽略的 `main/chant_bridge_local.h` 和私有插件 `pairing.json`；不得提交或公开这些文件及配套固件、插件。UDP 使用 HMAC-SHA256 挑战应答；HTTP 验证配对密钥、限定私有 IPv4 来源、请求体大小和单个在途任务。局域网 HTTP 未加密，应使用可信网络。只有明确按住按键才会打开麦克风，录音最多64 KB IMA ADPCM；录音和播放均由唯一音频任务执行。新固件在原 `/audio` 接口请求 `audio/x-passport-ima-adpcm`；桥接 v1.4 返回 12 字节 PVA1 头（标识、LE32 16000 Hz、LE32 样本数），后接单声道 IMA ADPCM（初始预测值和索引为零，高半字节优先），最多90秒。语音传输量约为原 PCM 的四分之一。独立下载任务写入24 KiB压缩队列，唯一音频任务先缓冲16 KiB（约两秒），再按512个样本解码播放；缓冲耗尽时先补充再继续。取消时等待下载任务退出后释放队列。头部、长度、时长检查拒绝截断或格式不匹配的数据。旧固件未发送此 Accept 头时仍返回 PCM，因此仅更新桥接即可启用搜索，播放改善须配套更新固件。桥接在合成完成时重新开始150秒的就绪任务保留期。对话期间推迟天气刷新，NVS 保存仍须音频任务确认静默，否则拒绝写入。

临时配网热点已改为免密码，仍限制一个客户端，十分钟自动关闭。本地固件使用被Git忽略的首次连接配置，成功连接后保存网络；忘记网络时保留配置标记，避免重启后自动恢复已忘记的预置网络。本地固件及私有凭据头文件不得公开。

## 离线二维码与主页快捷入口

主菜单顺序为扫描 Wi-Fi、二维码、佛音曲库、安庆天气、连接 Wi-Fi、语音音量、
Cindy 对话。第一项直接打开现有扫描页并请求扫描，确定键可重扫；网络子菜单
仍保留扫描入口。主页第一项按上键可循环到最后一项 Cindy 对话。

扫描页标题直接绘制 Wi-Fi 图标（三条弧线和圆点），旁边显示“扫描Wi-Fi”，
不依赖图标字体或位图，其它页面隐藏该图标。大号字体生成器现在从应用源码提取实际标题和主页菜单名称，
主机测试将这些字符串与生成字体的字形表逐项比较，修复扫描页之前的四个缺字方框，
同时覆盖已存网络页标题，不通过更改编码或隐藏占位方框掩盖缺字。
直接绘制可避免为一个图标引入整套字体。

二维码页离线显示本地黑白 I1 图片，长按确定或双击上键返回主页，普通按键不会
发起语音对话或影响音乐播放。标题移到图片上方，回复画布与正文隐藏。二维码
保留四模块白边，采用整数倍像素缩放，在标题和页脚之间的 224 像素方形区域内显示。

执行 `python3 tools/prepare_chant_qr.py /path/to/qr.jpg` 准备本地图片，要求 OpenCV
支持二维码编码。脚本解码原图，去掉装饰图标并重新编码同一目标，验证打包后的
显示位图仍可解码到相同内容，不输出二维码目标。此次图片生成 196 像素方图，
索引数据 4,908 字节。源图和预览 `assets/images/chant-qr-local*`、生成头文件
`main/chant_qr_local.h` 均被 Git 忽略。公开源码没有此头文件也能构建，页面显示
未设置提示。不得公开私有二维码图片或包含它的固件；本功能不改写 NFC 标签。

主机导航和位图解码检查不代表实际屏幕扫码通过。真机仍需检查手机扫码、标题／
电量／页脚间距、退出后的图片隐藏、中文字体，以及进入扫描页后自动扫描。

## 语音上传失败恢复

桥接 v1.5 与配套固件针对间歇性 HTTPS 上传失败增加恢复处理：

- 同一段录音使用一个随机请求编号，上传最多尝试两次；桥接对同源、同编号返回
  原任务，不重复识别。身份错误、限流和任务忙不会自动重试。
- JSON 响应带明确的 Content-Length。设备完整读取分片正文，临时读取超时继续
  等待；正文有总时限与长度上限，取消时退出。日志记录失败阶段、HTTP 状态和
  剩余堆，不记录凭据或语音内容。屏幕区分配对、拒绝访问、任务忙、服务故障与超时。
- 录音结束后尝试收紧 ADPCM 缓冲，再建立 TLS 连接。失败任务同取消任务一样，
  在下次录音完成后清理；失败清理不会阻塞麦克风启动。
- 桥接允许新提问替换同源的失败任务；新固件还可明确替换未播放的就绪回复。
  正在识别或回答的任务仍返回忙。语音下载完成后，回复保留 150 秒供重试，
  同时允许接收下一次提问；识别、思考、合成阶段转换时刷新保留时限。

固件还在一轮对话中复用连接，避免每次轮询重新进行 TLS 握手。公网连续真机
对话已完成，用户确认可以听到正常回复。这些检查覆盖当时的网络和已安装的
桥接 v1.5，不证明所有网络都可靠，也不代表尚未安装的 v1.6 检索策略已经通过
真机验证。长时间弱网运行和取消后的恢复仍需进一步真机验证。

## 多个常用网络

应用最多保存六组Wi-Fi，以带版本及有效性校验的单个NVS数据项保存，并迁移旧版单网络设置。开机先连接上次成功的网络；连续两次失败就尝试下一组，全部不可用时延长重试间隔。已连接时不会为了寻找其它网络而主动断开。本地私有配置只合并一次用户提供的三处网络，同名网络更新密码，不重复添加。手机新提交的凭据，只有匹配网络取得IP后才加入列表；列表满时显示保存失败，不静默删除原有记录。已有忘记网络操作会清除全部常用网络，同时保留初始化标记，避免重启后恢复已清除的预置记录。凭据不进入维护文档、日志或代码提交。

## 跨网络语音连接

设备先用认证的局域网广播查找桥接，最多等待约三秒。找不到时使用被 Git 忽略的
`main/chant_bridge_local.h` 中的 `CHANT_BRIDGE_REMOTE_URL`；不配置则保持仅局域网。
取值必须是类似 `https://voice.example.com` 的 HTTPS 域名入口，不含路径、端口、
查询参数、账号或片段。上传、任务轮询、回复文字和语音都使用相同配对密钥。
每轮对话固定使用选中的连接，不通过另一入口重复上传同一录音。

远程请求使用已有证书包，校验证书、域名和有效期，拒绝重定向，并等待 SNTP
时间就绪。远程失败不会降级成公网 HTTP。一轮对话串行复用同一个 HTTP 客户端，
用于上传、查询、文字和语音；仅成功且正文完整的响应保留连接，失败、截断或服务端
要求关闭时先断开再重试。GET 请求前清除上传正文及请求编号等头部。下载任务只在
查询和文字读取结束后借用客户端，退出并被等待后再释放；下一轮录音前释放整个会话。
日志只统计请求次数与实际建连次数，不记录地址、密钥或语音。
Cloudflare Tunnel 可终止 HTTPS，仅转发语音服务到 `http://127.0.0.1:18765`；
桥接看到回环来源，仍检查配对密钥和任务归属。不开放 Cindy 应用接口或整个内网。

跨网络使用要求固定域名、隧道在线、Mac 唤醒且 Cindy 桥接运行。域名和私有配对
配置不进入 Git；仓库默认构建不含远程入口，使用占位密钥，需本地配置后配对。
构建检查不代表远程服务已连通，也不代表设备录音、播报已实测。

脱敏后的配套源码、私有配置要求与任务权限恢复方法见[语音桥接源码](chant-bridge-source.zh_CN.md)。
